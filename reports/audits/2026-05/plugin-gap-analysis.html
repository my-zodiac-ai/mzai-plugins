TL;DR

  1. mzai-plugins has zero hooks and zero plugin-level slash commands. All three projects rely on inline hooks in .claude/settings.json. Largest reusability gap.
  2. ~70% of useful agents/skills live in local .claude/ folders, never extracted to the marketplace. They get re-invented per project.
  3. The marketplace is MZAI-stack-only (NestJS + Vue 3 + Quasar). companion-ai (Nuxt 3 + Prisma + Tailwind) and astro-ai-landing (Nuxt 4 + @nuxt/content) are unsupported.
  4. speckit is duplicated 4× — 1 plugin + 3 local copies. Maintenance trap.
  5. High-value missing categories: i18n coverage automation, Prisma migration safety, SSE streaming review, GSAP audit, blog/content SEO, Capacitor mobile lifecycle.

5. Risks & Honest Caveats

  1. Drift between marketplace and anthropic-skills:*. Host already lists 50+ mirroring entries. Pick one canonical source before lifting more.
  2. Hooks have a security blast radius. All hook scripts must quote variables, use absolute paths, never interpret content as code, and have a kill switch.
  3. Platform pivot in-flight (2026-04). companion-ai → multi-tenant means companion-stack-toolkit may need rework once extraction lands. Don't over-invest.
  4. eda-compliance vs architecture-auditor overlap. May be redundant. Audit before lifting.
  5. astro-ai-landing's Nuxt 4 + oxlint stack is bleeding-edge. Pin Nuxt-specific skills with version compat notes.
  6. The "v-model" speckit skills (10 files) appear largely unused based on local files. Validate adoption — could be dead-weight to deprecate.
